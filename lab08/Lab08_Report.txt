1. Disk Scheduling (Phase 2):

จากการทดลอง FCFS มีระยะเคลื่อนหัวอ่านรวม 640 cylinders ส่วน SCAN มีระยะรวม 331 cylinders เพราะ FCFS ให้บริการตามลำดับคำขอที่เข้ามา ทำให้หัวอ่านเคลื่อนกลับไปกลับมาระหว่างตำแหน่งที่ห่างกัน

ส่วน SCAN ทำงานคล้ายลิฟต์ โดยเริ่มจากตำแหน่ง 53 เคลื่อนไปทางหมายเลขที่สูงขึ้นและให้บริการคำขอระหว่างทางจนถึงปลายดิสก์ที่ 199 จากนั้นจึงกลับทิศทางมาให้บริการคำขอที่เหลือ ทำให้ลดการเคลื่อนที่กลับไปกลับมา และมีระยะเคลื่อนหัวอ่านน้อยกว่า FCFS สำหรับชุดข้อมูลนี้ ทั้งนี้ ตัวเลขที่วัดเป็นระยะทาง ไม่ใช่เวลา Seek Time โดยตรง

2. I/O Bound Concept:

I/O Bound หมายถึงงานที่ความเร็วถูกจำกัดด้วยการรับส่งข้อมูล เช่น การอ่านข้อมูลจากดิสก์ไม่ทันการประมวลผล เมื่อโปรเซสต้องรอข้อมูล โปรเซสนั้นจะหยุดรอ I/O และยังใช้ CPU ทำงานต่อไม่ได้

หากไม่มีงานอื่นพร้อมทำงาน CPU อาจว่างเป็นส่วนใหญ่แทนที่จะใช้งาน 100% แต่หากมีโปรเซสอื่น ระบบปฏิบัติการสามารถจัดให้ CPU ประมวลผลโปรเซสเหล่านั้นระหว่างรอได้ ดังนั้น งานที่เป็น I/O Bound ไม่ได้หมายความว่า CPU ทั้งเครื่องต้องว่างเสมอไป

3. AI Industry Connection (Phase 3):

การเก็บ Dataset เป็นไฟล์ภาพแยกกัน 1,000,000 ไฟล์ ทำให้ระบบต้องค้นหาข้อมูลกำกับไฟล์ ตรวจสอบสิทธิ์ และเปิด–ปิดไฟล์ซ้ำจำนวนมาก จึงเพิ่มภาระ I/O หากการโหลดข้อมูลช้ากว่าการประมวลผลของ GPU จะทำให้ GPU ต้องว่างงานเพื่อรอข้อมูล เรียกว่า GPU starvation และทำให้การเทรนใช้เวลานานขึ้น

การรวมข้อมูลเป็นไฟล์หรือชุดไฟล์ที่อ่านต่อเนื่องได้ เช่น TFRecord หรือ WebDataset ช่วยลดการเปิด–ปิดไฟล์ และเอื้อต่อการอ่านล่วงหน้าของระบบ จึงช่วยส่งข้อมูลให้ GPU ได้ต่อเนื่องมากขึ้น ทั้งนี้ ประสิทธิภาพยังขึ้นอยู่กับรูปแบบการจัดเก็บและการเข้าถึงข้อมูลด้วย

จากการทดลอง การอ่านไฟล์เล็ก 1,000 ไฟล์ใช้เวลา 0.0507 วินาที ส่วนไฟล์ใหญ่หนึ่งไฟล์ใช้เวลา 0.0010 วินาที โดยโปรแกรมคำนวณจากค่าก่อนปัดทศนิยมได้ว่าการอ่านไฟล์เล็กใช้เวลาประมาณ 52.78 เท่าของการอ่านไฟล์ใหญ่

ผลนี้แสดงประโยชน์ของการลดภาระการจัดการไฟล์ในสภาพแวดล้อมที่ทดลอง แต่ยังได้รับผลจากแคชของระบบ และไม่ได้วัด GPU starvation โดยตรง นอกจากนี้ ไฟล์นามสกุล .tfrecord ในสคริปต์เป็นเพียงไฟล์ไบนารีจำลอง ไม่ใช่ TFRecord ที่มีโครงสร้างจริง
